1. O QUE ESTÁ INCLUÍDO
---------------------------------------------------------------------
Site público: Início, Comunidade, Clãs, Guias, Clips, Notícias, Entrar,
Perfil, Privacidade, Termos + qualquer página criada no painel.

Painel /admin (CMS visual):
 - Editor com pré-visualização em tempo real (computador, tablet, telemóvel).
 - Páginas: criar, editar, duplicar, reordenar (arrastar), eliminar,
   definir página inicial, mostrar/esconder no menu.
 - Secções: 17 tipos (destaque, texto, imagem+texto, cartões, chamada para
   ação, imagem, galeria, vídeo YouTube/TikTok, regras, Discord, FAQ, aviso,
   listas dinâmicas de clips/notícias/guias/clãs, formulário de clips,
   login Google, perfil, espaço). Arrastar da paleta para a pré-visualização,
   reordenar arrastando, duplicar, eliminar.
 - Edição de texto diretamente na pré-visualização (duplo clique).
 - Estilo por secção: fundo (cor/imagem), cor do texto, espaçamentos,
   largura, alinhamento, bordas, cantos, âncora, esconder em telemóvel/PC.
 - Tema global: cores, fontes (12, servidas localmente), cantos,
   espaçamento, bordas, estilo de fundo.
 - Cabeçalho e rodapé: logo (carregar/substituir), altura, posição,
   menu, links extra, botão de destaque, aviso legal.
 - Anular/refazer (Ctrl+Z / Ctrl+Shift+Z), Ctrl+S para guardar,
   gravação automática do rascunho a cada 45 s.
 - Rascunho vs. publicado; histórico de versões com pré-visualização
   e restauro; pontos de restauro manuais.
 - Gestão de notícias, guias, clãs, clips, utilizadores e permissões,
   biblioteca de imagens, estatísticas, backups e registo de atividade.

Backend: Netlify Functions + Netlify Blobs (sem SQL, sem Supabase).
Todos os dados sobrevivem a novos deploys.


2. O QUE FUNCIONA LOGO E O QUE PRECISA DE CREDENCIAIS
---------------------------------------------------------------------
Funciona logo após o deploy (com as 2 variáveis do ponto 4):
 - Todo o site público com o conteúdo inicial.
 - Painel /admin com palavra-passe de administrador: editor, notícias,
   guias, clãs, media, backups, estatísticas.

Precisa de configuração externa:
 - Login Google dos jogadores (perfil, publicação de clips) → Google
   Client ID (ponto 5). Sem ele, a página Entrar mostra um aviso.
 - Link do Discord e redes sociais → config.json ou painel > Design >
   Definições do site. Enquanto vazio, o botão do Discord aparece
   desativado (nada é inventado).
 - Email de contacto na política de privacidade → mesmo sítio.

NOTA: não é usado nenhum Google Client SECRET. O login usa Google
Identity Services (ID token), validado no servidor com as chaves
públicas da Google. Só o Client ID (público) é necessário.


3. PUBLICAR NO NETLIFY (PASSO A PASSO)
---------------------------------------------------------------------
IMPORTANTE: o Netlify Drop (arrastar uma pasta para o browser) NÃO
executa o build nem instala as funções. Este projeto precisa de build.
Usa UM destes métodos:

MÉTODO A — Git (recomendado)
 1. Cria um repositório no GitHub (pode ser privado) e envia o conteúdo
    deste ZIP (não envies a pasta node_modules nem public/).
 2. No Netlify: abre o site existente "dancing-bubblegum-470ffb"
    > Site configuration > Build & deploy > Link repository
    (ou "Add new site > Import an existing project" para um novo).
 3. Confirma as definições (já estão no netlify.toml):
      Build command:       npm run build
      Publish directory:   public
      Functions directory: netlify/functions
 4. Define as variáveis do ponto 4 ANTES do primeiro deploy.
 5. Deploy. Cada "git push" volta a publicar; os dados ficam intactos.

MÉTODO B — Netlify CLI (sem Git)
 1. Instala Node.js 20+ e corre:  npm install -g netlify-cli
 2. Na pasta do projeto:          npm install
 3. Liga ao site existente:       netlify link
 4. Publica em produção:          netlify deploy --build --prod
    (o --build corre o build e empacota as funções)

O build não precisa de nenhum ficheiro .env.


4. VARIÁVEIS SECRETAS NO NETLIFY (OBRIGATÓRIO)
---------------------------------------------------------------------
Netlify > Site configuration > Environment variables > Add a variable.
Marca a opção "Contains secret values" quando disponível.

  SESSION_SECRET   (obrigatória) — texto aleatório com 32+ caracteres.
                   Gera um, por exemplo, com:
                   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ADMIN_PASSWORD   (obrigatória) — palavra-passe do painel /admin,
                   mínimo 10 caracteres (recomendado 16+).
  ADMIN_EMAILS     (opcional) — emails Google separados por vírgulas que
                   ficam automaticamente administradores ao entrar.
                   Ex.: tu@gmail.com,outro@gmail.com
  GOOGLE_CLIENT_ID (opcional) — se preferires não pôr o Client ID no
                   config.json. Tem prioridade sobre o config.json.

Estas variáveis existem APENAS no servidor. Nunca aparecem no HTML,
no JavaScript público nem no config.json. Depois de as alterar, faz
um novo deploy (Deploys > Trigger deploy).

Netlify Blobs não precisa de configuração: fica disponível
automaticamente para as funções do site.


5. CONFIGURAR O LOGIN GOOGLE (OAUTH)
---------------------------------------------------------------------
 1. Vai a https://console.cloud.google.com/ e cria um projeto
    (ex.: "ROB RUN Portugal").
 2. APIs e serviços > Ecrã de consentimento OAuth (Google Auth Platform):
    - Tipo: Externo. Nome da app: ROB RUN Portugal. Email de suporte.
    - Domínio autorizado: netlify.app (ou o teu domínio próprio).
    - Links para a política de privacidade e termos:
        https://dancing-bubblegum-470ffb.netlify.app/privacidade
        https://dancing-bubblegum-470ffb.netlify.app/termos
    - Âmbitos: só os básicos (openid, email, profile).
    - Publica a app ("Em produção") para qualquer pessoa poder entrar.
 3. Credenciais > Criar credenciais > ID do cliente OAuth
    - Tipo: Aplicação Web.
    - Origens JavaScript autorizadas:
        https://dancing-bubblegum-470ffb.netlify.app
        (e o teu domínio próprio, se tiveres; para testes locais
         acrescenta http://localhost:8888 e http://localhost)
    - URIs de redirecionamento: não são necessários.
 4. Copia o "ID do cliente" (termina em .apps.googleusercontent.com)
    para "googleClientId" no config.json (ou para a variável
    GOOGLE_CLIENT_ID) e volta a publicar.
 5. NÃO precisas do "Client secret". Não o coloques em lado nenhum.

Para te tornares administrador também pela conta Google: define
ADMIN_EMAILS, ou entra primeiro com a palavra-passe e atribui a função
em Painel > Utilizadores.


6. config.json (CONFIGURAÇÃO PÚBLICA)
---------------------------------------------------------------------
Este ficheiro é copiado para o site e qualquer pessoa o pode ler.
É seguro porque só contém dados públicos. O build recusa-se a publicar
se encontrar chaves com nomes como "secret", "password" ou "token".

 - siteUrl, googleClientId
 - community: nome, slogan, descrição, email de contacto, aviso
 - links: discord, tiktok, youtube, instagram, x, twitch
 - visual: cores e fontes iniciais
 - privacy: dias de sessão, meses até apagar contas inativas (0 = nunca),
   nº de backups automáticos e de versões a manter

Os valores de comunidade/links/visual são o PONTO DE PARTIDA. Depois de
publicares pelo painel, mandam os valores definidos no painel.


7. USAR O PAINEL /admin
---------------------------------------------------------------------
Abre https://<o-teu-site>/admin e entra com a ADMIN_PASSWORD.

Editor do site
 - Esquerda: Páginas (arrasta para reordenar o menu), Secções da página,
   "+ Adicionar" (paleta) e "Design" (tema, cabeçalho/logo, rodapé,
   definições).
 - Centro: pré-visualização real. Clica numa secção para a editar,
   faz duplo clique num texto para o escrever ali mesmo, usa a barra
   da secção (⠿ arrastar, ↑ ↓, duplicar, eliminar).
 - Direita: inspetor (separadores Conteúdo e Estilo).
 - "Guardar rascunho" grava sem afetar o público. "Publicar" põe o
   rascunho no ar e cria uma versão. "Versões" permite pré-visualizar
   e restaurar qualquer versão.
 - Links aceitam /pagina, https://..., mailto: e atalhos como
   {{discordUrl}}, que usam o valor das Definições do site.

Funções (permissões)
 - Jogador: publica e elimina os próprios clips.
 - Moderador: notícias, guias, clãs, clips, suspender jogadores, media,
   estatísticas, atividade.
 - Administrador: tudo, incluindo editor do site, permissões, backups,
   eliminar utilizadores e imagens.

Clips
 - Publicação automática (sem aprovação prévia), só YouTube (vídeos e
   Shorts) e TikTok, validados e normalizados no servidor.
 - Anti-spam: 30 s entre publicações, máx. 5/hora e 15/dia por
   jogador, vídeos duplicados recusados, campo armadilha anti-bot,
   verificação oEmbed de que o vídeo existe e é público.
 - Moderação: editar, ocultar, destacar, eliminar, suspender o autor.

Backups
 - Automático todos os dias (função agendada "maintenance"), manual a
   qualquer momento, descarregar em JSON, importar e restaurar.
 - Antes de qualquer restauro é feita uma cópia do estado atual.


8. SEGURANÇA E RGPD
---------------------------------------------------------------------
 - Autenticação e permissões verificadas sempre no servidor; o papel
   do utilizador é lido do armazenamento em cada pedido.
 - Token Google validado no servidor (assinatura, emissor, audiência,
   expiração, email verificado).
 - Sessões: cookie __Host-rr_sid HttpOnly + Secure + SameSite=Lax,
   assinado com HMAC; a sessão vive no servidor e pode ser revogada
   (suspender um utilizador termina as sessões dele).
 - CSRF: token double-submit (cookie SameSite=Strict + cabeçalho) e
   verificação de Origin / Sec-Fetch-Site.
 - XSS: HTML rico sanitizado no servidor (lista branca) e no browser;
   todo o resto é inserido como texto; Content-Security-Policy estrita;
   URLs e cores validadas; SVG recusado nos uploads; ficheiros
   verificados pelos "magic bytes".
 - Limitação de pedidos no login (por pseudónimo de IP, ver abaixo),
   nos clips (por utilizador) e nos uploads.
 - IPs: nunca guardados em claro. Para travar ataques ao login guarda-se
   até 24 h um hash HMAC do IP com chave secreta que muda diariamente
   (interesse legítimo, explicado na política de privacidade).
 - Estatísticas sem cookies, sem IPs, sem identificadores.
 - Vídeos YouTube/TikTok só carregam depois de o visitante clicar
   (YouTube em modo youtube-nocookie). Fontes servidas localmente.
 - Direitos RGPD no perfil: exportar dados e eliminar conta.
 - Retenção automática (função diária): sessões expiradas, registos de
   limitação, contas de jogadores inativas há 24 meses, auditoria
   com mais de 180 dias, backups automáticos além de 14.
 - Revê a política de privacidade no painel (página Privacidade) e
   preenche o email de contacto.

11. RESOLUÇÃO DE PROBLEMAS
---------------------------------------------------------------------
 - "falta a variável SESSION_SECRET" → ponto 4, depois novo deploy.
 - O painel diz "A API não está disponível" → o site foi publicado sem
   build (ex.: Netlify Drop). Usa o método A ou B do ponto 3.
 - Botão Google não aparece → confirma googleClientId e as "Origens
   JavaScript autorizadas" (têm de coincidir exatamente com o endereço,
   com https e sem barra no fim).
 - "Conflito de edição" no editor → outra sessão gravou o rascunho;
   escolhe carregar do servidor ou substituir.
 - Alterei o config.json e nada mudou → depois da primeira publicação
   pelo painel, os valores do painel têm prioridade; edita-os em
   Design > Definições do site.
